# m4code

m4code is a native desktop app, written in Rust with [GPUI](https://gpui.rs), that runs coding agent sessions (Claude Code, Codex, OpenCode and Google Antigravity) in one window on Windows, macOS and Linux. It is a personal project with rough edges: macOS and Linux are lightly tested, and the macOS build isn't notarized. Issues and pull requests are welcome.

## What it does

Each session is a conversation with Claude Code, Codex, OpenCode or Google Antigravity in m4code's own chat view. m4code talks to each agent through the [Agent Client Protocol](https://agentclientprotocol.com) (ACP), and sign-in stays with the agent. Settings → General picks the default model for new sessions across all enabled harnesses. Claude Code sessions run through Anthropic's [Claude Agent SDK](https://code.claude.com/docs/en/agent-sdk/overview) with your own `claude`, and need Node and npm. The first one installs the SDK into m4code's data folder. Anthropic's [terms](https://code.claude.com/docs/en/legal-and-compliance) don't allow third-party apps built on the Agent SDK to use a Claude Free, Pro, Max or Ultra sign-in without Anthropic's approval, and Anthropic may enforce that without notice. m4code uses whatever sign-in your `claude` has, so with a subscription sign-in you use Claude Code sessions in m4code at your own risk. An API key, or a cloud provider such as Bedrock or Vertex, is allowed. Codex sessions need Node, because m4code runs Codex through its ACP adapter from npm. The chat view takes Claude Code's keyboard shortcuts, such as Esc to interrupt, Esc twice to edit your last message, Shift+Tab to change mode and Up for earlier messages. Shift+Enter starts a new line in either message box. While the agent works, a Working line with a spinner shows at the bottom of the chat. Settings → General decides what a message you send meanwhile does. Steer, the default, gives it to the agent in the turn it is working on. Claude Code reads it once its current step is done, and until then it waits above the message box. Codex, OpenCode and Antigravity stop their turn and start again with it. Queue makes it wait for the turn to end, in a list above the message box, where you can edit or remove it before m4code sends it. Cmd/Ctrl+Enter does the other one for a single message, and slash commands always wait. When an agent asks a question, the arrow keys or the mouse highlight an option, and Enter picks it. For Claude Code's questions, you can type your own answer in the message box instead. Your own messages show their Markdown formatting in the chat. Settings → Keyboard lists every keyboard shortcut; they can't be changed yet. Pick up a session here, in a project's menu, lists the default agent's sessions in that folder, including ones started in a terminal, and opens the one you choose. Quit it in the terminal first. The welcome screen is the message box for a new session. Home and chat share a Send button on the right. Empty or whitespace-only drafts cannot be sent, including with Enter. Its chips pick the model from any enabled harness, the project, the effort level and the branch or worktree. The branch list explains deletion restrictions and shows the paths of external worktrees too. A missing worktree folder stays listed and cannot be selected. A chat's message box has the same chips, the branch chip included. The branch chip's dropdown starts work in a new worktree in one click. Type a name in its search box, or leave it blank for a random name, then choose New worktree to branch from main, or from current to branch from the checkout you are in. A typed name that isn't a branch also gets a Create branch row. Inside a chat, click the model pill (or press Alt+P / Option+P) to search and pick any model across enabled harnesses or drag the effort bar, and click the permission pill to open the permission mode dropdown; Escape or clicking outside closes either dropdown. The permission dropdown lists Auto mode whenever Claude Code offers it for your account. Picking a model served by another harness hands off the conversation in place when you send your next message, after the current turn ends. Returning to a harness resumes its saved provider session and sends the intervening conversation. A failed handoff restores the original session and the unsent draft. When you ask an agent to switch models, it does so with m4code's set_model tool, and list_models gives it the model names. A switch to a model on another harness hands the conversation to that harness when the turn ends. m4code's tools that open, read or link sessions, switch models or move a session to another worktree never ask you to confirm: the agent calls them only when you asked for what they do. An agent can open a new session in a project with a model and effort of its choosing; the new session takes your default permission mode. Settings → Harnesses enables or disables Claude Code, Codex, OpenCode and Antigravity. Each harness's popup lists its models. The model picker shows the ticked models. Every model starts ticked, and the last one can't be unticked. Claude Code's popup also holds its account switcher and the Claude in Chrome switch for new sessions. m4code starts each Claude Code session without the tools meant for the claude.ai app, such as scheduled tasks, push notifications and the claude.ai connectors. It removes them for that session only, so Claude Code in a terminal keeps them. The slash command menu leaves out commands m4code's own controls cover, such as /model and Codex's /approvals. Every harness popup has the same subagent and edit controls and uses the same status format. Antigravity shows its terms warning directly under the subagent toggle. With the toggle on, each ticked model can run as a subagent. Codex and OpenCode subagents default to enabled with edits allowed when those settings have not been saved. Existing off and read-only choices stay as they are. Antigravity stays opt-in for Claude Code's native integration. The sidebar footer shows usage limits only for connected harnesses that have a limits adapter. Settings → Skills browses `skills.sh`, installs single `SKILL.md` packages or whole GitHub repositories, and symlinks enabled skills globally or per project into each active harness. Installed skills are grouped by the GitHub repository they came from. Update fetches the latest version of one skill, Update repo does it for every skill from that repository, and Update all does it for every installed skill. Toggles stay as they were. With a project picked as the scope, the page also lists the skills that project's repository ships in its own folders, such as `.claude/skills`. m4code only reads those folders. Before each message in a git repository, m4code saves the working tree. Review changes, under the message box, then shows what changed since your last message, hunk by hunk. Each hunk can be kept or reverted. A comment on a line goes back to the agent as `@path#L12: comment`, and Cmd/Ctrl+Enter in a comment sends all of them. In editor mode, a button beside the selected lines, or beside the line under the mouse, opens the same comment box. Enter adds `@path#L12-30: comment` to the message box on a line of its own, and Cmd/Ctrl+Enter sends it. The sidebar starts with the project selector and Settings on its right. Drag the right sidebar's cards into any order, and m4code keeps it. Around the chat, m4code adds a sidebar of running and recent sessions (Ctrl+Z, or Cmd+Z on macOS, reopens the last one you closed), notifications when a background session finishes or asks something, an editor mode (Ctrl+Shift+E) that also works on Home for the selected project, preserving each project's tabs and unsaved edits, usage meters, a GitHub pane, cards Claude draws inline, sessions that move between git worktrees, extra accounts that share one configuration, a `skills.sh` browser and toggle panel (Settings → Skills) that installs `SKILL.md` packages and symlinks enabled skills globally or per project into each active agent's skills folder, and cross-agent subagents configured in Settings → Harnesses. Codex subagents need Node and a `codex login`, OpenCode subagents need `opencode` on PATH, Antigravity subagents need the Antigravity CLI (`agy`) installed and signed in, and with Allow edits on, each acts without Claude Code's permission rules. Read-only Antigravity runs from its own folder in m4code's data, whose hook refuses every tool but reading and searching, so your own Antigravity rules, skills and MCP servers don't load there. Google's [Antigravity terms](https://antigravity.google/terms) and [FAQ](https://antigravity.google/docs/faq) forbid using another company's agent, such as Claude Code, with a personal Google sign-in. That covers the Free, AI Plus, Pro and Ultra plans. Google can suspend or terminate the Antigravity and Gemini CLI accounts of anyone who does, so turn Antigravity subagents on at your own risk. With Codex subagents on, the sidebar also shows Codex's 5-hour and 7-day limits, which m4code reads from the session logs in `~/.codex`; with Antigravity subagents on, it shows Antigravity's limits for each group of models, from `agy`'s own `/usage`, asked every five minutes at no token cost. Their last saved readings show at launch and refresh in the background. Settings lists the rest.

Claude Code, Codex and OpenCode sessions share m4code's `spawn_subagent`, `list_subagents`, `send_subagent_message`, `wait_subagent` and `stop_subagent` MCP tools. Children run in the parent's working folder without taking focus. When a child's turn ends, m4code sends its report to the parent, which shows it folded among the thinking and tool steps. Click the step to read the report, or Open to show the child. `wait_subagent` is only for a parent that must have the report before it can go on. A subagent's chat has a bar above it with a link back to its parent, the child's provider and its state. The right sidebar lists a session's subagents with their provider logos and states, and folds the finished ones into one row. The list includes the harness's own subagents, such as Claude Code's Agent tool and its `m4code:` types; clicking one unfolds its step in the chat and scrolls there. Follow-ups use the same child session, including after stopping it. Stopping a parent stops its children. A read-only parent cannot grant edits to a child, and user questions still need an answer. Claude Code's native subagent integration remains available. Enabled Codex and OpenCode providers register a default-model subagent even before their model catalogs load. The shared MCP instructions name every subagent tool so each supported provider can discover them. The shared tools exclude Antigravity for now. In the Home editor, line comments go into the new-session composer; Cmd/Ctrl+Enter sends them and starts the session.

m4code schedules compaction at the next idle boundary once reported context reaches 80%. It uses the adapter's advertised native compact command and keeps the provider session. Claude Code's mod and OpenCode's session configuration turn off native automatic compaction. Codex retains a native fallback that m4code cannot disable; the status panel says so. An adapter without verified compaction support shows that limitation. m4code does not replace an unsupported session with a generated summary. Returning to a provider keeps its session continuity and avoids resending the context it already has.

While a custom subagent works, its own view in Claude Code's tasks list streams its messages, reasoning, plan and tool steps and command output. The main conversation stays as it is until the subagent hands back its report. The first Codex run takes longer while npm downloads the adapter. Claude can choose a Codex subagent's effort when it starts one (`max` runs as Codex's `xhigh`); otherwise Codex uses the effort in `~/.codex/config.toml`.

A message Claude sends a running Codex subagent reaches it in the task it is working on, and its answer streams like the rest. OpenCode takes such messages too if its version supports them. Antigravity and older OpenCode versions get the message as a follow-up once the current turn ends, as does a subagent that has already finished. Antigravity takes the effort Claude asks for, capped at the highest thinking level its model offers.

## What it touches

m4code never calls the Anthropic API or deletes a transcript, and it changes Claude Code's settings only when you flip a switch. In a git repository, each session keeps its 20 newest working-tree snapshots as commits under `refs/m4code/`. They never touch your index, branches or stash, but `git log --all` shows them. Its network use is GitHub (the update check, the GitHub pane and installing skills), `skills.sh` when you browse or search Skills, npm for the Claude Agent SDK and the Codex adapter, OpenAI once you use Codex sessions or turn on Codex subagents, the providers you set up in OpenCode once you turn on OpenCode subagents, and Google once you turn on Antigravity subagents. Terminal contents are never logged.

## Development

You need stable Rust, plus Visual Studio Build Tools on Windows or the headers GPUI builds against on Linux, and [just](https://just.systems): `just run`, `just test`, `just ci`. `src/` is the app, `vendor/gpui-base/` is a patched copy of the editor crate (`Cargo.toml` says what the patch changes and when to drop it), `mod/` is the Claude Code plugin each session loads, `bridge/` is the Node script that runs Claude Code sessions through the Claude Agent SDK (its lockfile pins the SDK), and `web/` is the site. `AGENTS.md` has the conventions. A debug build keeps its data in its own folder, so it runs beside the installed app; a second app on the same folder says m4code is already running and quits. To release, bump `version` in `Cargo.toml` and push a `vX.Y.Z` tag.
